# 麒麟清单数据模型与本地服务契约

麒麟清单（KylinList）以**实体**为核心：任务与笔记共用同一张表，靠 `kind` 区分；桌面便签只是任务在某一台设备上的窗口投影。本文描述 `kylinlist.db` 的本地数据契约，以及仅为未来可选账号同步保留的边界。当前模型不设置工作区；文件夹与清单负责组织全部本地实体。

最后核对：2026-11-17。当前契约使用 **schema v10（仅新库）、备份元数据 v6（仅读写当前版本）**；开发阶段不保留旧数据库升级、旧备份转换或旧内链双读入口。旧预览库不再迁移，直接用新的空数据目录重建；启动仍不会擅自删除或重置已有数据库。正文内链仅采用 `[[UUID|字面别名]]`／`[[UUID]]`，独立检查项模型已移除，Markdown 任务列表仍属于正文。五种分组、类型化拖放与事件上下文继续沿用。实施与历史边界见[数据模型重构实施指引](data-model-refactor.md)。本文同步实现契约；完整Windows离屏／原生自动化结果见[更新说明当前条目](updates.md#当前实现与验证状态)，这些结果不表示用户视觉或麒麟真机验收已经通过。

## 当前范围：只有本地 SQLite

- 默认数据库是 Linux 的 `~/.local/share/kylinlist/kylinlist.db`；Windows 使用 Qt `AppLocalDataLocation` 下的 `kylinlist.db`。`KYLINLIST_DATA_DIR` 或 `--data-dir` 可指定独立的开发、测试目录。
- 使用 SQLite，启用 `foreign_keys=ON`、WAL、`busy_timeout` 和 `synchronous=NORMAL`。所有连接、仓储和调度器遵守其线程归属，写操作在事务中提交。
- 数据库标识为 ASCII `KLST` 对应的 `application_id`（`0x4B4C5354`），当前 `user_version = 10`。只接受完全为空的新库和标识／版本正确的当前 v10 库；新库直接建成 v10，不经过任何旧版本。
- 已有文件先只读检查标识、版本与是否为空，再决定是否建立可写连接／启用 WAL。**v5/v6/v7/v8/v9、错误标识、未知或未来版本均在写入前拒绝**，不升级、不转换正文、不补旧列，不生成升级备份或一致性副本；不能在拒绝前切换日志模式、写 pragma 或修改原文件。
- 不保留旧库迁移器或兼容分支；拒绝旧库是当前明确的数据边界，不静默重置用户文件，也不以旧库内容或其他旧产品文件作为新库回退来源。
- 旧 `notes.db` 不读取、不转换、不删除。
- 当前没有登录、账号体系、服务器端点或同步服务。`local_meta.signed_in` 初始为 `0`；预留表和字段不代表功能已实现。

`Database::openAt(path, error)` 供临时库与测试使用。打开、pragma、建库和检查全部成功后才算可用；失败必须关闭连接，不能留下半初始化的库供业务写入。

## 实体：任务与笔记

单表 `entities` 承载两种实体，`kind ∈ {task, note}`。

| 字段 | 含义与约束 |
|---|---|
| `id` | UUID 主键，创建后不变 |
| `kind` | `task` / `note`，唯一决定实体行为的字段 |
| `title` | 非空（trim 后） |
| `body_markdown` | 正文，纯 Markdown 源码，允许为空 |
| `folder_id` / `list_id` / `section_id` | 组织引用，`list_id` 必填 |
| `parent_id` | 父子任务；**笔记恒为 NULL**，且父与子必须同为 `task` |
| `sort_order` | 清单内手动顺序 |
| `status` | `active` / `completed` / `abandoned`；笔记保留原值但不参与行为 |
| `deleted_at_utc_ms` | 回收站，非空即已软删除 |
| `start_at_utc_ms` / `due_at_utc_ms` | 带时刻的计划，UTC 毫秒；时间段分别保存开始／结束 |
| `all_day_date` / `all_day_end_date` | 全天单日或包含式起止日期，ISO `YYYY-MM-DD` |
| `has_schedule_range` | 明确区分单日与时间段，即使起止同日；全天范围必须有结束日，时刻范围必须有两个端点 |
| `timezone` | IANA 时区，默认 `Asia/Shanghai` |
| `recurrence_series_id` / `occurrence_key` | 重复实例身份，成对出现且唯一 |
| `priority` | 0 无 / 1 低 / 2 中 / 3 高 |
| `pinned_at_utc_ms` | 置顶时间；NULL 表示未置顶 |
| `revision` / `server_revision` | 本地乐观锁版本 / 未来服务端版本 |
| `created_at_utc_ms` / `updated_at_utc_ms` | 审计时间 |
| `completed_at_utc_ms` / `abandoned_at_utc_ms` | 与 `status` 严格同步 |

### 笔记的规则

- **笔记没有父子概念**，`status` 与优先级不参与笔记行为；`CHECK(kind='task' OR parent_id IS NULL)` 由数据库强制。
- 笔记现在可以保存日期、时间段和正常一次性提醒，并实际收到通知；提醒弹窗不提供“完成”。第三列仍不显示笔记日期或日期提示，笔记也不进入任务时间聚合、完成／放弃历史或任务进度统计。
- 转换类型继续保留所有字段、提醒、附件与清单。任务转为笔记后，任务完成状态与优先级仍保留但不生效；转回任务后恢复对应行为。
- 新建笔记的 `status` 为 `active`，仅用于满足非空约束。

### 字段级约定

- 已移除：`favorite`（星标）、贴到桌面状态。贴到桌面降级为一个动作，状态只存在于 `desktop_notes`。
- 新增：`pinned_at_utc_ms`（置顶）。**置顶不是星标，不是贴桌面**，只影响列表排序。
- 正文只有 Markdown 一种格式，不再有 `content_format` 列。
- 回收站与业务状态完全分离：恢复不改动 `status`。

## 组织：文件夹与清单

任务与笔记使用**同一套**组织，用户可以按同一层级给两者分类。

| 表 | 职责 |
|---|---|
| `folders` | 单层文件夹，只容纳清单；没有 `parent_id`，不允许文件夹嵌套 |
| `lists` | 清单。`folder_id` 可空：为空时平铺显示在左侧清单列，不为空时归入对应文件夹 |
| `sections` | 清单内分区，随清单级联清理 |

- `lists.kind ∈ {task, note}` 表示**任务清单 / 笔记清单**。它只决定在该清单中新建实体的默认 `kind`，以及前端图标和提示语；不限制实际实体类型，两种实体可以放入任意清单，转换类型也不要求移动清单。
- 全库有且只有一个系统收集箱（`is_inbox=1`），不可删除；新实体必须落入收集箱或用户清单。收集箱默认创建任务。
- 新建或改名时，`lists.name` 为 trim 后 1–64 个 UTF-16 码元；既有长名称在未改名时保留原值，不因归档、移动或外观修改而截断。`icon` 为空表示默认图标，否则保存不超过 16 个 UTF-16 码元的 emoji 文本；`color` 为空表示无颜色，否则为 `#RRGGBB`。名称、图标、颜色、文件夹通过一次创建或更新事务保存。`folders` 同样保存可选 `icon`，名称约束与清单一致。
- 顶层平铺清单与文件夹共享一个展示顺序，文件夹内部清单另有同级顺序；各容器以连续非负 `sort_order` 持久化，旧全零数据按“平铺清单在前、文件夹在后，各自 sort_order,id”保持原展示。拖动只生成目标意图，`TaskStore` 从当前快照重读并在一笔事务完成移动、建夹和顺序规范化；组织区末尾及空白支持移到顶层末尾。取消建夹命名弹窗不创建文件夹、不改清单归属/顺序；标题或正文的失焦保存仍按独立编辑会话正常执行。
- 文件夹是可选导航范围：通过 `entity.list_id → lists.folder_id` 聚合成员，不能依赖实体上可能为空的旧 `folder_id`。默认 List 分组，置顶实体跨成员清单汇总，其余活动任务按清单分节；也可切换其他 GroupMode，而不改变成员资格。归档清单不进入活动聚合。文件夹视图的快速添加选择实际成员清单，空文件夹禁止快速添加，不能暗中改写收集箱。
- `lists.archived_at_utc_ms` 为 0 表示未归档，大于 0 表示已归档。归档继承自清单，不改写内部实体的 `status`、日期、提醒和附件；系统收集箱禁止归档。
- 归档清单从普通清单分组移入“已归档的清单”，其活动实体不进入“所有／今天／明天／最近7天／已过期”聚合视图，也不提醒、不物化活动桌面便签；直接打开该清单仍能查看。已完成、已放弃和垃圾桶保留历史与恢复可见性。取消归档恢复资格，未投递的历史提醒按正常调度规则处理。
- 删除用户清单时，在同一事务内将其全部任务和笔记（含已完成、已放弃及已软删除实体）移至系统收集箱、清空旧分区与文件夹引用，并标记进入回收站；未删除实体记录本次删除时间，已在回收站的实体保留原 `deleted_at_utc_ms`，`status`、提醒与关联内容不变。恢复后留在收集箱；永久删除才清理实体和附件。删除文件夹不清除其中清单，清单变为平铺。
- `view_defs` 预留自定义视图：`spec_json` 一整块保存 `{scope, renderer, sections}`，新增段类型或筛选条件都只改 JSON，不动物理表。本期只内置默认视图，不提供编辑界面。

## 正文与 Markdown 任务列表

当前实体没有独立检查项类型、集合、表或业务 UI；详情与桌面便签也不保留 `NoteChecklist`。标题与 Markdown 正文是文本内容的真源，需要独立日期、提醒或层级的内容使用任务／子任务。

- 正文支持段落、三级标题、无序／有序列表、Markdown 任务列表、引用和分割线；块菜单与格式岛修改同一份 `body_markdown`，不另外保存块对象。
- `- [ ]`／`- [x]` 是 **Markdown-only 复选框**：编辑区点击只切换正文中的标记，沿用正文撤销与编辑会话，不创建检查项 UUID、独立完成状态、业务进度或新表。
- 不读取或转换旧 `checklist_items`、嵌套 `checklist` 或根 `checklistItems`。旧库在打开前拒绝，旧备份版本及当前 v6 中夹带的旧结构在导入前拒绝；没有双表示校验后转换的兼容入口。

## 提醒

`reminders` 与实体一对多，每条有独立 UUID、触发时刻、相对规则、顺序和审计时间。

- **未删除、活动状态且所属清单未归档的任务，以及未删除且清单未归档的笔记参与调度**。调度器、Store 投递入口、SQL 投递事务和展示前复查使用一致资格。归档时已显示的提醒弹窗会关闭，稍后提醒也不能绕过归档状态。
- `rule_json` 是版本化的正常一次性提醒规则：明确相对锚点（计划／开始／结束／绝对）、提前量、全天日期偏移与本地时刻；`trigger_at_utc_ms` 保存已解析 UTC 时刻。修改计划时由 `resolveReminder` 统一重算，稍后提醒只把当前提醒改为新的绝对时刻。
- **没有持续提醒**：不保存开关或持续状态，不重复投递，不提供对应按钮。多个提醒仍是各自独立的一次性提醒。
- `reminders.entity_id` 是普通单列外键，不带 `kind` 复合约束，转换实体类型不需要移动提醒。
- `reminder_deliveries` 以 `(reminder_id, installation_id)` 记录本机投递去重：先持久化凭证，再发通知；失败保留重试资格。修改触发时刻必须使旧凭证失效。
- 应用退出或关机期间不会提醒，恢复运行后补发；不承诺后台服务、邮件或手机推送。笔记通知提供打开、稍后提醒和关闭，没有任务“完成”动作。

## 引用：正文内链

内部引用的唯一正文语法是 **`[[UUID|字面别名]]` 与 `[[UUID]]`**，目标可为任意任务或笔记，可跨清单、跨文件夹：

```markdown
下周把 [[8f14e45f-4c49-4a37-9f0e-2f3f1b6c9d10|周报模板]] 的字段补齐
查看当前标题：[[8f14e45f-4c49-4a37-9f0e-2f3f1b6c9d10]]
```

- UUID 必须合法。带 `|` 的别名是**单行字面文本**，按原值显示，不因目标改名而重写，也不作为 Markdown／HTML 执行；写出时把换行归一为空格，不接受跨行引用别名。不带别名时才在渲染时使用目标当前标题。正文源码始终保留原引用。
- 渲染后的内部导航 `href` 是 **裸 UUID**，不是自定义 URL scheme；编辑区与预览区共用内部导航判断。外部链接仍使用普通 Markdown 链接，并仅按已支持的 http／https／mailto 地址处理。
- **不解析、不生成、不扫描旧 `kl:` 链接，不做双读、自动改写或迁移回退。** 无效语法保持普通文本；不存在或在回收站的目标按当前断链／状态展示策略处理，不能让整篇正文渲染失败。
- 输入 `[[` 或从“关联任务/笔记”入口插入 `[[` 后打开非模态候选，按任务／笔记**标题包含**查询，不限于前缀。中文输入法 preedit 期间不把未提交组合文本当成最终查询或确认；Escape 只取消候选，不插入、不删除原查询或误触正文命令。
- 链接悬浮提供复制／编辑入口；编辑弹层仅有“文本”和“链接”两个输入字段，分别编辑显示文字与外部地址／内部实体标识，确认才更新源码，取消不写入。内部引用保存回规范的双中括号语法。
- 格式岛、补全、块菜单和链接编辑保存**绝对 UTF-16 源码偏移**，通过 `sourceSelection()`／`selectSource()` 在源码与呈现之间恢复，不能跨 FocusOut 保留原始 `QTextCursor`。`setContent`／`setStore`／`setEntityId` 改变编辑上下文时推进 `contextGeneration`；旧代际弹层与迟到回调不得修改新的实体或正文。
- 复制正文时保留原生纯文本／富文本剪贴板格式，并附带应用私有 Markdown 源码 MIME；应用内粘贴保留关联目标和完整源码，一次粘贴只占一次撤销。Qt5.12 的惰性 selection MIME 由适配层包装，不直接给其追加不可枚举的数据格式。
- **反向引用按需查询**：只扫描上述双中括号语法中的合法 UUID，不维护第二份业务关系列表。引用不构成任务层级，A→B→A 合法；未来规模需要时只能新增可重建的派生边表。

## 桌面便签

`desktop_notes` 保存**某一台设备上**的窗口状态：颜色、几何、层级、z-order、是否打开，以 `(entity_id, device_id)` 唯一。

- 它**不是实体状态**：不参与视图筛选、不进列表标记、不进入同步与备份。
- 只有任务可以物化便签窗口；笔记从不贴到桌面。
- "贴到桌面"与"关闭便签"是同一种操作的两个方向：创建/关闭本机窗口，不改变实体本身。
- 关闭便签不删除实体；实体完成、放弃、进入回收站或所属清单归档时窗口随之关闭，未保存正文先落盘。清单取消归档后，保留的本机打开状态可重新物化窗口。

## 范围、分组与排序

**先筛选，再分组；分组与筛选正交。** `ViewSpec` 模块的 `contains()` 统一范围、搜索、归档资格与终态显隐，计数和列表使用同一条件；`TaskGrouping` 模块的 `groupEntities()` 再按 `GroupMode` 构建展示组。旧 `ViewRenderer` 仅为兼容展示标识，不再改变筛选资格，界面不再提供“清单视图／时间视图”二选一入口。

| 范围 | 接纳条件（起止日期按实体 IANA 时区换算，今天由应用时区给出） |
|---|---|
| 所有 | 未删除的活动任务及笔记，排除归档清单；可通过 `showCompleted` 放行两种终态 |
| 单清单／收集箱 | 指定 `list_id` 的未删除实体；显式清单可查看归档内容；可放行两种终态 |
| 文件夹 | 通过 `lists.folder_id` 聚合成员清单，不依赖实体旧 `folder_id`；活动聚合排除归档清单；可放行两种终态 |
| 今天 | 与今天相交的时间段，以及全部截止日早于今天的逾期任务 |
| 明天 | 单日为明天，或包含式时间段与明天相交 |
| 最近7天 | 包含全部逾期，以及单日或时间段与今天至今天+6 相交 |
| 已过期 | 截止／范围结束日期早于今天；保留 scope，不提供独立侧栏入口 |
| 已完成／已放弃 | 非删除任务的对应业务状态，保留归档清单历史 |
| 垃圾桶 | 已删除任务和笔记，保留归档清单历史 |

日期类范围仅接纳未删除、活动状态且所属清单未归档的任务；无日期任务与笔记不进入。即使笔记保存日期，也不进入这些聚合。选择 Time 分组本身**不会**把它们从“所有”或普通清单里过滤掉。置顶同样不豁免范围条件。搜索同时覆盖任务与笔记。

侧栏入口可始终显示、有实体时显示或隐藏（界面文案为“显示／有内容时显示／隐藏”），仅保存在本机设置，不进入业务备份；隐藏入口不阻断内链等显式实体导航。过期分组的顺延仅在聚合智能范围提供，普通清单（含收集箱）不提供；按各任务有效日期平移至今天，保留时刻、跨度和原提醒，整批事务提交。

### 五种 `GroupMode`

| 模式 | 规则 |
|---|---|
| `List`（清单） | 普通任务按实际清单分组，清单依 `sortOrder → name → id` 排列；文件夹默认此模式 |
| `Time`（时间） | 六个互斥日期桶；除文件夹外各 scope 默认此模式 |
| `Created`（创建时间） | 过去7天／过去30天／更早／未知时间；纯展示、禁拖 |
| `Priority`（优先级） | 高 3 → 中 2 → 低 1 → 无 0 |
| `None`（无分组） | 普通任务平铺、不画普通组标题；不是取消全部特殊区 |

- 单清单和收集箱不提供没有意义的 List 选项；旧偏好若读到 List，回退 Time。
- 本机 `QSettings` 的 panel 偏好使用 `grouping/<scope>/<id>`，值为 `list/time/created/priority/none` 字符串；清单用清单 ID、文件夹用文件夹 ID、其他 scope 用 `all`。不同范围独立记忆，不进业务库或 `.klb`。
- 活动视角统一顺序为 **pinned → 普通模式组 → notes → completed → abandoned**。置顶活动任务与置顶笔记汇总后不再重复；终态不进入置顶区。`None` 只去掉普通任务组标题，仍保留已有特殊区。
- `showCompleted` 同时放行已完成和已放弃，二者在活动列表底部独立展示；显示设置的“显示已完成和已放弃”复选框与原菜单 quick toggle 共用同一个偏好。日期筛选不因该开关放行终态。
- **历史视角 Completed／Abandoned／Trash 也支持全部五模式，且确实按该模式拆组**，不再折叠成一个终态标题。历史分组忽略 pin，不追加活动视角的 notes／终态页脚，List 可包含已归档清单；各模式只读、禁止拖放，不借重分组更改日期、优先级或状态。

Time 桶边界与稳定键如下；规格中的 `expired` 对应实现 `TimeBucket::Overdue`／`time:overdue`，不按中文标题反推落点。**智能筛选按范围相交，六个互斥展示桶按 `effectiveDate`（单日计划日／范围结束日）归组**；因此一个范围可同时被今天和明天筛到，但只落入一个稳定的展示桶，跨组拖放也按结束日平移并保持跨度。

| 桶语义 | 实现稳定键 | 有效日期 |
|---|---|---|
| expired（已过期） | `time:overdue` | 早于今天 |
| today | `time:today` | 今天 |
| tomorrow | `time:tomorrow` | 今天+1 |
| next7days | `time:next7days` | 今天+2 至今天+6 |
| later（稍后） | `time:later` | 今天+7 起 |
| undated（无日期） | `time:undated` | 无有效日期 |

Created 按应用时区创建日距今天的天数分桶：过去7天为 0..6，过去30天为 7..29，更早为 ≥30；缺失、无效或未来创建时间落未知桶。它与“最近7天”智能筛选不是同一个概念。

### 层级与组内全序

- 同清单、同状态类别的可见子任务继承可见主任务的显示组，紧随其后连续展示；主任务被筛选排除时，仍可见的子任务作为普通行显示。终态子任务不跟随活动主任务，跨清单关系不继承展示组。
- 折叠仅改变显示，不改筛选计数、实体数据或完整子树操作集合；每个实体只出现一次。
- 活动组内先 `sortOrder ASC`，再按模式自然字段，最后 `id ASC`。Time／List／Priority／None／置顶的任务回退有效日期升序、创建时间降序；Created 与笔记回退创建时间降序。旧全零或非连续 rank 也按同一全序解释，不能拿 rank 当数组下标。
- 终态默认按对应 `completedAt`／`abandonedAt`／`deletedAt` 倒序，再按创建时间倒序、`id ASC`，不使用手动 rank。历史视角只改变组归属，不伪造任务的真实状态或时间。
- 不提供“排序”“顺序”设置 UI。分组切换不写实体字段，也不生成活动日志。

### 类型化拖放与移动

UI 只构造 `TaskDrop::Intent`（源 ID、模式、源／目标 `GroupKey`、`Placement`、锚点／主任务、目标顺序、时间目标日期）；`TaskStore::applyDropIntent()` 重读最新仓储快照、校验并原子提交。显式“移动到”共用 `TaskStore::moveEntityToList()` 的完整子树规则，不再用多 bool 落点 API。

| 落点 | 允许的业务改写 |
|---|---|
| 同父级、同显示组重排 | 仅 rank；不归一日期、不重设优先级或 pin，也不改变父子关系 |
| 同显示组跨父级 Before／After | 以锚点的真实 parentId 确定目标同级；脱父成为根项后，若自身日期／优先级／置顶不满足目标组，则补齐对应属性，不能仅比较继承的显示组 |
| 真正跨 Time 组 | 最近合法日期：expired=昨天、today=今天、tomorrow=明天、next7days=后天、later=今天+7；undated 清空 `allDayDate/startAt/dueAt`，从无日期进入日期组建立纯日期 |
| 真正跨 Priority 组 | 只把优先级改为目标 0..3，另按跨组规则处理脱父与离 pin |
| 跨 List 组／显式移动到 | 移动完整持久化子树，含被搜索或筛选隐藏、折叠、已完成、已放弃的后代；保留子树内部关系，清理旧分区与组织引用 |
| 进入／离开 pinned | 进入时设置 pin，离开时清 pin；同组排序保留每个实体原 pin，不因继承主任务显示组误置顶 |
| `AsChild` | 同清单进行中任务设为子任务；只改 parent／order，不暗改 date、priority 或 pin，后代关系保留 |

- 有日期的跨 Time 改期按真实有效日期差值平移原日期字段，保留明确时刻、跨日跨度、提醒和重复身份；无日期互转也保留提醒。不能把同桶第 3–6 天的任务强制改成后天；旧非连续 `sortOrder` 不应破坏这些语义。
- 子任务独立跨组时脱离原主任务；拖主任务跨清单时则带完整子树。显示组可能来自主任务，Store 必须区别显示继承和实体真实属性。
- `orderedIds` 只是可见顺序提示，不能直接从零覆盖全组 rank。Store 从最新完整目标兄弟集合中仅抽出源项按落点稳定插回，保留隐藏项与其他成员的最新相对顺序；同父同组的可见同级顺序未变则零写。实际重编号的隐藏成员全部进入同一次 GroupMove／CAS／事务；置顶区任务和笔记共同遵守 rank，不能按类别强行分开。
- 校验源组是否仍有效、锚点归组与前后位置、顺序 ID 唯一性、清单可用性、完整祖先链及循环；锚点不能位于源子树内。非法或陈旧意图、CAS 失败全部零写入，父级 touch 与实体保存合并，避免同批重复推进 revision。
- completed／abandoned／trash 不接受拖放；Notes 只接受笔记排序或置顶笔记返回，不隐式转换 Task／Note。所有历史视角整体禁拖；显式移动命令可按自身资格移动终态，但不改其状态。
- Created 模式下真实拖动手势给第三列底部 `WorkspaceToast` 提示，Store 同样拒绝，零写入。空目标组仅在允许拖动期间追加到现有行之后，结束、取消或离开后移除，不在手势中移动原行。

### 有效日期与扩展边界

- `effectiveDate` 是截止／逾期锚点：单日取计划日，范围取包含式结束日；范围相交使用 `scheduleIntersects`，未来排序使用 `scheduleStartDate`，三者不隐式混用。
- **过期分组按日期判定，不按钟点**：今天 09:00 截止、现在 15:00 仍属于今天，不算已过期；详情按钮可在截止时刻已过时显示稳定红色，但这不改变智能分组口径。
- 计划时刻按实体 IANA 时区换算；审计时间和“今天”的当前日期仍由应用时区给出。全序最终用 `id ASC` 兜底，避免同值抖动。
- 范围筛选、分组、呈现分别负责资格、组归属、绘制；未来新增日历／看板等呈现不能偷偷改变范围或写业务字段。

## 时间与时区

- 默认时区为 IANA 名称 `Asia/Shanghai`，写入 `local_meta.default_timezone`；它不是硬编码的 `UTC+8`。
- 带时刻的时间一律以 UTC 毫秒整数持久化，字段带 `_utc_ms` 后缀；只在显示和编辑时换算。
- 全天使用 `all_day_date`，不把当地午夜伪装成 UTC 时刻。
- 开始与截止同时存在时必须 `start <= due`。
- 审计时间一律 UTC；用户可见的日期以应用时区呈现。

### 日期编辑与展示语义

- 日期选择器以完整 `ScheduleValue` 为草稿：单日、明确时刻、同日／跨夜／跨日时间段、多个提醒和重复规则一起编辑。只选日期时写入 `all_day_date`；明确时刻（包括 `00:00`）写入 `due_at_utc_ms`；时间段另有开始端点或包含式全天结束日。
- 四个快捷项以点击时的应用时区今天为基准：今天、明天、今天 +7 天、下个月同日；目标月没有同日时截断至月末。点击快捷项立即走接受／保存／关闭链，已有明确时刻保留，未选时刻仍是纯日期。普通月历点选只修改草稿，仍由“确定”提交。
- 时间段有开始／结束日期、各自时间和全天开关；新时刻范围默认结束晚 1 小时。全天隐藏时间输入但保留草稿；结束早于开始会阻止保存并显示错误，不静默交换端点。取消外层或子弹层不写入业务库。
- 保存前重读最新实体并独立比较日期、提醒与重复基线；正文等无关修改正常合并，另一个编辑器已改变调度时拒绝旧弹窗覆盖。快速添加用同一 `saveSchedule` 一次事务创建实体，不产生先创建后补日期的半成品。
- 第三列笔记不显示日期文字或提示；第四列任务和笔记均可打开日期选择器。任务与笔记可保存多个正常提醒，任务完成后相对提醒按下一次出现重新解析。

## 重复

`recurrence_series` 的权威配置是版本化 `rule_json`；`rrule` 仅保留非权威的简单频率摘要，不参与下一次出现计算。实体通过 `(recurrence_series_id, occurrence_key)` 唯一标识一个周期，`occurrence_ordinal` 与 `completion_count` 明确持久化进度，不塞进 occurrence key。

- 公历支持日／周／月／年、多选星期、多月日、固定月末、每月第 N／最后一个星期几、普通周一至周五工作日、年度月日或年度第 N／最后一个星期几。固定 31 日跳过没有 31 日的月份；只有 `-1` 表示真实月末。
- 支持按到期日期或按完成日期推进，以及有序去重的自选日期。结束条件为一直、结束日期或 2–200 次；最后一条完成正常结束，不把“无下一次”当保存错误。
- 农历每月／每年使用本地 1900–2100 年表，保留原始月日、真实月末与闰月策略；短月可临时截断但不污染后续锚点。无网络、法定节假日、黄历或艾宾浩斯记忆法。
- `dtstart` 与 IANA 时区提供原始系列锚点，保持间隔相位和农历语义。时刻范围重复保留本地开始／结束钟点及包含式日期跨度，不把它简化成固定 UTC 小时数。

完成重复任务时保留本次记录，并在同一事务内按规则生成下一次（若已结束则不生成）。生成凭证以 `source_id` 唯一，防止重启或重试产生重复实例；撤销完成时若下一实例已产生附件、子任务或其他修改，必须拒绝撤销并保留数据。

## 附件

`attachments` 保存 UUID、所属实体、原始文件名、受管相对路径、MIME、字节数、**SHA-256**、是否图片、排序与本机可用状态（`available` / `missing` / `corrupt`）。

- 文件内容放在数据目录 `attachments/` 下，命名 `<附件UUID>_<安全扩展名>`；不存 BLOB，不引用用户原始路径。
- 单个 1 字节至 2 MiB；图片必须真实解码通过。
- 同一附件 UUID 的内容不可变；替换内容应生成新 UUID。
- 附件入口支持本地单／多文件选择和整个详情及子控件的拖入。导入将文件复制到受管目录，保留源文件。点击打开时，应用为通过完整性校验的文件创建带实际后缀的临时副本，交给系统默认程序。
- 拖入前先 `finishEditing()`，保存失败则零导入；与原选择器共用大小、图片解码、哈希与落盘校验。多文件按文件逐次提交，遇错报告并停止，已成功文件保留，不承诺整批回滚。
- 写入顺序：先原子写文件，再提交元数据；删除顺序：先提交元数据，再清理文件。清理失败只留孤儿文件，不允许元数据指向不存在的文件。

## 活动日志

`entity_events` 保存实体生命周期与白名单实质变更，不是所有 UI 操作的流水账。写入端与 `ActivityTimelineWidget` 共用 `ActivityPolicy.h` 的可见事件白名单；历史原始事件可以保留，但不重新展示已排除的噪声。

| 字段 | 说明 |
|---|---|
| `id` | 事件 UUID |
| `entity_id` | 实体 UUID，**不加外键**，使实体永久删除后日志仍存在 |
| `entity_kind` / `entity_title` | 冗余快照，供实体消失后仍能展示；创建摘要含标题 |
| `batch_id` | 同一次事务的事件共享，用于批次追踪与未来幂等；不是用户可见摘要 |
| `type` | `created` / `changed` / `kind_changed` / `trashed` / `restored` / `deleted` / `attachment_added` / `attachment_removed` / `reminder_added` / `reminder_removed` |
| `field` | `changed` 的实质字段白名单，见下文 |
| `old_value` / `new_value` | 标量保存前后值；文本事件只存完整新内容 |
| `context_json` | 当前 schema v10 的事件上下文，领域字段为 `EntityEvent.context`，持久化为 **JSON 对象**，默认 `{}`，备份事件键为 `context` |
| `occurred_at_utc_ms` | UTC 毫秒 |

### 记录规则

- **只记录实质变更**，相同值保存不产生日志。生命周期及附件／提醒增删按动作记录。
- **changed** 白名单包含 `title`、`body`、`status`、`due`、`start`、`allDayDate`、`allDayEndDate`、`hasScheduleRange`、`priority`、`list`、`parent`、`timeZone`、`recurrence`、`recurrenceRule`、`tags`、`listArchived`、`reminder`／`reminder.*`、`attachment`／`attachment.*`。标签仍使用既有 `tags` 模型；本轮加号／`#` 候选接入此字段，不建立第二套标签存储。
- **排序、置顶、section／文件夹归组、图标／颜色等外观和纯本机状态不记活动**。包括窗口几何、提醒投递凭证、分组与其他显示偏好；不能因纯排序落盘推进 revision 就生成 `changed` 噪声。
- **文本字段**（`title`、`body`）按编辑会话记录：开始时分配独立会话 UUID，保留该编辑器初始快照；离开编辑器及其自有弹层、切换实体、关闭窗口或退出时结束，自有格式／补全／链接菜单的焦点交接不能误判为结束编辑。会话结束确有变化才各记一条，`new_value` 为完整新内容；详情和桌面便签各有独立会话与基线。没有活动会话的直接保存也只记录真正变化的文本。
- `kind_changed` 保留前后类型；任务字段保留、暂停行为，而不是删除字段。
- `context` 保存当时可读名称快照，例如 `oldParentTitle/newParentTitle`、`oldListName/newListName`、`attachmentName`、`listName`。主任务或附件以后改名、删除仍可读；旧空上下文降级为通用动作，不把 UUID、NULL、批次号或整个对象塞进摘要。
- 当前没有账号，不虚构 Actor、用户昵称或头像。父级的用户文案使用“主任务”，创建事件显示任务／笔记及其标题。

### 存储、刷新与展示

- 日志只增不改、不设上限、不做裁剪；不进入全量内存快照，按实体惰性查询，索引 `(entity_id, occurred_at_utc_ms)`；永久删除后仍保留。
- 实体与事件同事务提交。`TaskStore::eventsChanged(entityId)` 在提交后通知；即使只落日志、实体本身未变化，也必须发出。时间线只刷新当前实体；隐藏期间标记 dirty，下次显示补刷。
- 详情第四列的 `ActivityTimelineWidget` 位于正文滚动区下部，和标题、正文共用 `DetailScroll`，可关闭、不打开独立日志对话框；附件另在底栏上方的独立有界滚动面板中，不进入该正文滚动流。事件最新在前，标题／正文摘要保持简短，不能把全文塞入一行。
- 几何为 20px 标记、14px 摘要、12px 时间、32px 文字左缩、20px 条目间距与 1px 连接线；时间行 20px，主题色来自语义令牌。精细 UI 约束见 [UI 对齐契约](ui-alignment-contract.md)。

## 备份 `.klb`：全量导出与覆盖恢复

备份是**镜像**，不是增量：一次导出再导入，业务数据与导出前完全一致。

### 导出

- 导出当前数据库的**全部业务数据**，不按清单或当前视图裁剪。
- 包含：`folders`、`lists`、`sections`、`recurrence_series`、`entities`、`tags` / `entity_tags`、`reminders`、`recurrence_links`、`attachments`（元数据与内容）、`view_defs`、`entity_events`（含 context）；不导出已移除的独立检查项表示。
- 根元数据显式保存 `defaultTimezone`；系统收集箱由备份清单中唯一的 `is_inbox=1` 记录恢复，不另存工作区或默认工作区 ID。
- 不包含设备本地数据：`installation_id`、`device_id`、`desktop_notes`、`reminder_deliveries`、`signed_in`、`sync_bindings`、`tombstones`、`outbox`。因此窗口位置与提醒投递记录不随备份回滚，它们属于设备而不是数据。
- 使用原子写入，中途失败不留下半个文件。

### 导入：先清空，再写入

1. 完整解析并校验容器（边界、UUID、引用完整性、状态与时间、RRULE、附件大小与 SHA-256）；任何一项失败都在动库之前终止。
2. 附件内容先写入暂存位置；在数据库事务提交前完成可恢复的新旧文件交换，任一步失败都恢复原文件并回滚数据库。
3. 单个事务内清空全部业务表，再按备份内容重建。`local_meta` 不整体清空：保留本机 `installation_id`、`device_id`，从备份唯一的系统收集箱恢复 `inbox_list_id`，从根元数据恢复 `default_timezone`，清空 `signed_in` 与同步游标。
4. 提交成功后仅清理旧附件备份，关闭全部便签与详情、重建导航与列表。替换期间禁止旧编辑器继续提交；失败时保留原界面与本机数据。
5. 失败则回滚事务、恢复原附件并清理暂存文件，本机数据保持原样。

- **UUID 原样保留**：正文双中括号内链、活动日志的 `entity_id`、重复链接与提醒归属都不需要改写。
- 导入是**破坏性操作**：必须二次确认，确认文案写明"本机现有全部任务、笔记与清单都会被删除"，并提示先导出。
- 导入完成后，对 `trigger_at` 不晚于导入时刻的提醒写入本机投递凭证、**不补发**，避免历史提醒集中弹出；未来提醒照常生效。
- 旧 `.knb`、旧 `.json` 与其他旧格式不迁移、不导入。

### 格式与上限

- 容器魔数 `KLB1`，元数据标识 `KylinList.Entities`，**导出与导入都只接受当前版本 6**：完整保存范围起止、范围标志、重复规则与进度、提醒规则，以及已有外观、归档和事件 context。夹带已移除的 checklist 表示即拒绝。
- v2/v3/v4/v5、未知未来版本及其他格式在动本机数据库或受管附件前拒绝；不保留隔离旧 codec、双表示转换、旧外观补齐或旧事件补字段的兼容入口。
- 当前 v6 中的 UUID、revision、更新时间与重复凭证按覆盖恢复契约保存；正文内链仅按当前双中括号语法解析，不借导入执行旧内链迁移。数据库 v10 的新库准入与备份 v6 的覆盖恢复是不同边界，均不提供旧版本升级。
- 容器总大小 2 GiB；元数据块 256 MiB，超出时返回明确错误，不解析、不部分写入；单个附件仍为 2 MiB。
- 附件内容按帧流式读写，不整体载入内存。

## 并发与事务

- 每条可变、可同步业务行都有 `revision`；更新与删除以 `revision` 为条件，陈旧写入必须被拒绝而不是覆盖。`entity_events` 是只增不改的追加日志，不参与更新或删除 CAS，是这条规则的明确例外，不设置 `revision`。
- 一次业务操作涉及的所有行（实体、提醒、附件元数据、重复链接、日志事件）在同一事务内提交。多文件附件导入则逐文件形成成功单元，不承诺整批原子。
- **修订推进规则**：会改变实体状态或关联数据的操作必须推进该实体的 `revision`，包括导入/移除附件、创建或迁移子任务。否则陈旧快照的删除会绕过保护，级联删掉新数据。
- 只在提交成功后替换内存快照并发信号；失败时保留原快照与用户编辑内容。
- 多表读取必须来自同一快照（单个读事务）。
- 多详情与便签的正文提交使用瞬态 `TextDraft`，携带实体、可选会话ID、标题／正文的基线与拟提交值，不增加表、schema或备份字段。每字段三方比较：本地未改保留当前值；当前已等于本地为无须写；当前仍等于基线才接受本地；否则冲突。任一字段冲突则整份正文提交零写，不推进revision／更新时间或追加事件；不存在或回收站实体返回不可用，不以旧草稿重新插入或恢复。
- 提交从当前实体合并，保留其他字段及桌面门面，仍经过既有校验、repository事务和CAS。保存期间同步观察者新生成的UI草稿不因旧结果成功而清空；目标／存储／编辑上下文变化时不把旧结果应用到新上下文。便签文字走同一提交链，`NoteManager`只持久化桌面字段，纯文字自动保存不隐式落盘尚未改动的默认窗口几何。
- UI接受其他编辑器的文本更新前，以`cancelEditSession`结清本会话实际成功保存过的字段，避免把别处的修改计入自己。它不是正文回滚：只按会话基线与自己的已保存终值补记必要事件，未保存草稿只在用户明确确认后丢弃。日志事务失败必须保留会话并返回失败；成功终结及自己的写入归因均在对外信号前完成，重入结束／取消不能重复记账。常规结束仍保留原来的会话基线与当前全文比较语义。

## 同步预留

`sync_bindings`、`tombstones`、`outbox` 只为未来可选账号同步预留。

- **未登录时，`sync_bindings`、`tombstones`、`outbox` 必须保持为空**；普通本地操作不得累积同步历史，首次绑定以全量快照为基线。
- 预留 outbox 带 `batch_id` 与 `base_server_revision`，用于未来整批幂等确认。
- 首次登录时：对方为空则上传，本地为空则下载，双方都有数据必须由用户显式选择，不能静默覆盖。
- 客户端不保存密码、密码哈希或令牌；令牌属于未来服务端与系统安全存储的职责。

## 扩展边界：哪些改动会动库，哪些不会

数据模型优先让新增交互复用既有实体与内容表示，避免为未证实的需求改造主表；这不是“永远不改 schema”的承诺。区分以下两类演进：

**不需要重建既有主表**（新增列、表或索引若改变持久化结构，仍需明确版本准入、事务失败处理和拒绝旧版本的测试；当前不提供旧库升级）：

- 新增视图、视图段、排序规则 → 只写 `view_defs.spec_json` 或代码里的内置定义；
- 新的相对提醒方式 → 在版本化 `reminders.rule_json` 中增加严格验证的字段或枚举；已解析 UTC 时刻与相对锚点继续同步保存；
- 全文搜索、看板/日历渲染、拖拽排序、批量操作、内链预览样式、日志展示与裁剪 → 新增派生表或纯代码；
- 重复规则扩展 → 扩展版本化 `recurrence_series.rule_json` 与引擎；`rrule` 摘要不是权威规则，不能靠压缩旧字符串代替；
- 同步 → 新增游标表与边表。

**需要一次性表重建**（SQLite 改 `CHECK` 或主键要重建表）：

- 新增第三种实体类型（如"习惯""倒数"）、第四种状态；
- 增改实体／状态的 CHECK 枚举或主键等约束。

需要独立日期、提醒或层级的内容继续用任务／子任务，不重建已移除的独立检查项模型。

因此当前的选择是：**枚举值收紧在 `CHECK` 里**（完整性优先，接受偶发的一次重建），**可变结构塞进 JSON**（视图定义），**不为未证实的需要预留空列**。
