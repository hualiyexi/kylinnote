# 麒麟清单数据模型与本地服务契约

麒麟清单（KylinList）以**实体**为核心：任务与笔记共用同一张表，靠 `kind` 区分；桌面便签只是任务在某一台设备上的窗口投影。本文描述 `kylinlist.db` 的本地数据契约，以及仅为未来可选账号同步保留的边界。当前模型不设置工作区；文件夹与清单负责组织全部本地实体。

实施步骤见[数据模型重构实施指引](data-model-refactor.md)。

## 当前范围：只有本地 SQLite

- 默认数据库是 Linux 的 `~/.local/share/kylinlist/kylinlist.db`；Windows 使用 Qt `AppLocalDataLocation` 下的 `kylinlist.db`。`KYLINLIST_DATA_DIR` 或 `--data-dir` 可指定独立的开发、测试目录。
- 使用 SQLite，启用 `foreign_keys=ON`、WAL、`busy_timeout` 和 `synchronous=NORMAL`。所有连接、仓储和调度器遵守其线程归属，写操作在事务中提交。
- 数据库标识为 ASCII `KLST` 对应的 `application_id`（`0x4B4C5354`），当前 `user_version = 5`。只接受完全为空的新库，或标识与版本均匹配的库；其他文件一律拒绝打开。
- 不做任何数据迁移：旧库、旧设置、旧备份都不读取、不转换、不删除。旧 `notes.db` 保留在原处，由用户自行处理。
- 当前没有登录、账号体系、服务器端点或同步服务。`local_meta.signed_in` 初始为 `0`；预留表和字段不代表功能已实现。

`Database::openAt(path, error)` 供临时库与测试使用。打开、pragma、建库和检查全部成功后才算可用；失败必须关闭连接，不能留下半初始化的库供业务写入。

## 实体：任务与笔记

单表 `entities` 承载两种实体，`kind ∈ {task, note}`。

| 字段 | 含义与约束 |
|---|---|
| `id` | UUID 主键，创建后不变 |
| `kind` | `task` / `note`，唯一决定实体行为的字段 |
| `title` | 非空（trim 后） |
| `body_markdown` | 正文，纯 Markdown 源码，允许为空 |
| `folder_id` / `list_id` / `section_id` | 组织引用，`list_id` 必填 |
| `parent_id` | 父子任务；**笔记恒为 NULL**，且父与子必须同为 `task` |
| `sort_order` | 清单内手动顺序 |
| `status` | `active` / `completed` / `abandoned`；笔记保留原值但不参与行为 |
| `deleted_at_utc_ms` | 回收站，非空即已软删除 |
| `start_at_utc_ms` / `due_at_utc_ms` | 带时刻的计划，UTC 毫秒 |
| `all_day_date` | 全天日期，ISO `YYYY-MM-DD` |
| `timezone` | IANA 时区，默认 `Asia/Shanghai` |
| `recurrence_series_id` / `occurrence_key` | 重复实例身份，成对出现且唯一 |
| `priority` | 0 无 / 1 低 / 2 中 / 3 高 |
| `pinned_at_utc_ms` | 置顶时间；NULL 表示未置顶 |
| `revision` / `server_revision` | 本地乐观锁版本 / 未来服务端版本 |
| `created_at_utc_ms` / `updated_at_utc_ms` | 审计时间 |
| `completed_at_utc_ms` / `abandoned_at_utc_ms` | 与 `status` 严格同步 |

### 笔记的规则

- **没有父子概念**：`CHECK(kind='task' OR parent_id IS NULL)`，数据库强制。
- **任务专属字段原样保留，但不参与任何行为**：`status`、`completed_at`、`start/due/all_day`、`recurrence_*`、`priority` 在转为笔记后既不显示也不生效；转回任务时自动复原，不需要用户重填。
- 因此**所有任务专属功能都必须显式过滤 `kind='task'`**，包括：今天/七天内/已逾期、时间视图、日历、提醒调度、便签物化、已完成/已放弃归档、进度统计。这条纪律收在单一入口，不允许各视图自行拼条件。
- 新建笔记的 `status` 为 `active`，仅用于满足非空约束。

### 字段级约定

- 已移除：`favorite`（星标）、贴到桌面状态。贴到桌面降级为一个动作，状态只存在于 `desktop_notes`。
- 新增：`pinned_at_utc_ms`（置顶）。**置顶不是星标，不是贴桌面**，只影响列表排序。
- 正文只有 Markdown 一种格式，不再有 `content_format` 列。
- 回收站与业务状态完全分离：恢复不改动 `status`。

## 组织：文件夹与清单

任务与笔记使用**同一套**组织，用户可以按同一层级给两者分类。

| 表 | 职责 |
|---|---|
| `folders` | 单层文件夹，只容纳清单；没有 `parent_id`，不允许文件夹嵌套 |
| `lists` | 清单。`folder_id` 可空：为空时平铺显示在左侧清单列，不为空时归入对应文件夹 |
| `sections` | 清单内分区，随清单级联清理 |

- `lists.kind ∈ {task, note}` 表示**任务清单 / 笔记清单**。它只决定在该清单中新建实体的默认 `kind`，以及前端图标和提示语；不限制实际实体类型，两种实体可以放入任意清单，转换类型也不要求移动清单。
- 全库有且只有一个系统收集箱（`is_inbox=1`），不可删除；新实体必须落入收集箱或用户清单。收集箱默认创建任务。
- 删除用户清单时，其中实体移回收集箱，不连带删除内容；删除文件夹不清除其中清单，清单变为平铺。
- `view_defs` 预留自定义视图：`spec_json` 一整块保存 `{scope, renderer, sections}`，新增段类型或筛选条件都只改 JSON，不动物理表。本期只内置默认视图，不提供编辑界面。

## 检查清单

`checklist_items` 是**挂在实体上的轻量条目**，任务与笔记都可用。

| 字段 | 说明 |
|---|---|
| `entity_id` | 所属实体，随实体级联删除 |
| `text` / `done` / `sort_order` | 条目文本、勾选状态、顺序 |

- 只有 UUID、文本、勾选和顺序；**没有日期、没有提醒、没有优先级**。需要独立日期或提醒的条目应升级为父子任务，而不是扩展本表。
- **正文里的 `- [ ]` 只是 Markdown 文本**：预览中渲染为静态符号，不计入进度、不可点击、不参与同步语义。清单的唯一真源是 `checklist_items`。
- 进度（如"清单 1/2"）由本表统计，不解析正文。

## 提醒

`reminders` 与实体一对多，每条有独立 UUID、触发时刻、顺序和审计时间。

- **只有任务参与调度**。笔记可以保留提醒行（类型转换时不清除），但调度器、提醒弹窗和"有提醒"标记都必须先判断 `kind='task'`。
- `reminders.entity_id` 是**普通单列外键**，不带 `kind` 复合约束。原因：复合外键会在任务转笔记的瞬间失败，与"字段保留"直接冲突。约束由查询层保证。
- `reminder_deliveries` 以 `(reminder_id, installation_id)` 记录本机投递去重：先持久化凭证，再发通知；失败保留重试资格。修改触发时刻必须使旧凭证失效。
- 应用退出或关机期间不会提醒，恢复运行后补发；不承诺后台服务、邮件或手机推送。

## 引用：正文内链

引用以 **Markdown 链接**形式写在正文里，scheme 为 `kl:`：

```markdown
下周把 [周报模板](kl:8f14e45f-4c49-4a37-9f0e-2f3f1b6c9d10) 的字段补齐
```

- `kl:` 后必须是合法 UUID；可以指向任意任务或笔记（可跨清单、跨文件夹）。
- **渲染时以目标的当前标题作为显示文字**，存储的链接文字只作兜底，因此目标改名后正文显示自动更新。
- 目标不存在：降级为普通文字并加警示样式，不能让渲染失败。目标在回收站：保留可点，附加状态标记。
- 编辑区是纯文本，链接不可点；预览区可点击跳转，悬浮显示预览。
- 悬浮预览：延迟 400–600ms，显示标题、类型、状态（任务显示完成/过期，笔记显示"笔记"）与正文纯文本摘要；鼠标离开即消失。
- **反向引用按需查询**：扫描正文中的 `kl:` 目标，不维护反向列表。当前数据规模下无需索引；实体数上千或引入服务端分页时，再增加可重建的派生边表。
- 不引用检查清单项；引用不构成层级，A→B→A 合法。

## 桌面便签

`desktop_notes` 保存**某一台设备上**的窗口状态：颜色、几何、层级、z-order、是否打开，以 `(entity_id, device_id)` 唯一。

- 它**不是实体状态**：不参与视图筛选、不进列表标记、不进入同步与备份。
- 只有任务可以物化便签窗口；笔记从不贴到桌面。
- "贴到桌面"与"关闭便签"是同一种操作的两个方向：创建/关闭本机窗口，不改变实体本身。
- 关闭便签不删除实体；实体完成、放弃或进入回收站时窗口随之关闭。

## 视图与排序

两种视图，共享同一条排序前缀。

### 置顶是排序前缀，不是视图

```
ORDER BY (pinned_at_utc_ms IS NOT NULL) DESC, pinned_at_utc_ms DESC, <视图内排序>
```

新增视图无需再处理置顶；它在所有工作视图中天然生效。归档类视图（已完成、已放弃、回收站）按各自时间倒序，不设置顶段。

### 清单视图

按清单浏览，段内顺序固定：

| 段 | 条件 | 排序 |
|---|---|---|
| 置顶 | `pinned_at` 非空，未完成、未删除 | `pinned_at DESC` |
| 已过期 | 非置顶，任务，有效日期 < 今天 | 有效日期 `ASC` |
| 未过期 | 非置顶，任务，有效日期 ≥ 今天 | 有效日期 `ASC` |
| 无日期 | 非置顶，任务，无有效日期 | `created_at DESC` |
| 笔记 | 非置顶，`kind='note'` | `created_at DESC` |

置顶段中的实体不再重复出现在后续段中。

### 时间视图

**先过滤，再分块。置顶不豁免过滤条件。**

- 每个时间视图由一个时间范围参数定义（今天、七天内、已逾期…）；
- 参与条件：实体具有有效日期，且该日期落在范围内。截止在今天之后的任务，即使置顶，也不属于"今天"视图；
- 笔记与无日期任务永不出现（它们只在清单视图可见）；
- 段内顺序与清单视图一致：置顶 → 已过期 → 未过期。

| 视图 | 范围 |
|---|---|
| 今天 | 有效日期 ≤ 今天 |
| 七天内 | 今天 ≤ 有效日期 ≤ 今天+7 |
| 已逾期 | 有效日期 < 今天 |

时间视图只在时间类范围（今天/七天内/已逾期）提供；清单、已完成、已放弃、回收站只用清单视图。

### 有效日期与过期判定

- 有效日期 = `due_at` 的日期；无 `due_at` 时取 `all_day_date`；再无则取 `start_at` 的日期。
- **过期按日期判定，不按钟点**：截止在今天 09:00、现在 15:00 的任务仍算"未过期"，避免列表在整点自行跳动。所有视图共用这一判定。
- 所有日期换算以应用时区（默认 `Asia/Shanghai`）为准。
- 排序必须是全序：各段最后以 `id ASC` 兜底，防止同值抖动。

### 扩展方式

视图 = 数据选择（范围 + 段定义 + 排序）+ 呈现方式（列表 / 日历 / 看板…）。两者分离：新增呈现方式不改变段定义；新增段定义不触碰渲染代码。

## 时间与时区

- 默认时区为 IANA 名称 `Asia/Shanghai`，写入 `local_meta.default_timezone`；它不是硬编码的 `UTC+8`。
- 带时刻的时间一律以 UTC 毫秒整数持久化，字段带 `_utc_ms` 后缀；只在显示和编辑时换算。
- 全天使用 `all_day_date`，不把当地午夜伪装成 UTC 时刻。
- 开始与截止同时存在时必须 `start <= due`。
- 审计时间一律 UTC；用户可见的日期以应用时区呈现。

## 重复

`recurrence_series` 保存 RFC 5545 风格的 `RRULE` 主体、时区、`dtstart` 与月锚点；实体通过 `(recurrence_series_id, occurrence_key)` 唯一标识一个周期。

当前引擎支持 `FREQ=DAILY|WEEKLY|MONTHLY` 与 `INTERVAL=1..999`，月重复保留 `anchor_day`（1/31 → 2/28 → 3/31）。`BYDAY`、`COUNT`、`UNTIL` 等扩展必须明确拒绝，不能静默忽略。

完成重复任务时保留本次记录，并在同一事务内生成下一次；生成基准是上次计划时间，不是实际完成时刻。生成凭证以 `source_id` 唯一，防止重启或重试产生重复实例；撤销完成时若下一实例已产生附件、子任务或其他修改，必须拒绝撤销并保留数据。

## 附件

`attachments` 保存 UUID、所属实体、原始文件名、受管相对路径、MIME、字节数、**SHA-256**、是否图片、排序与本机可用状态（`available` / `missing` / `corrupt`）。

- 文件内容放在数据目录 `attachments/` 下，命名 `<附件UUID>_<安全扩展名>`；不存 BLOB，不引用用户原始路径。
- 单个 1 字节至 2 MiB；图片必须真实解码通过。
- 同一附件 UUID 的内容不可变；替换内容应生成新 UUID。
- 写入顺序：先原子写文件，再提交元数据；删除顺序：先提交元数据，再清理文件。清理失败只留孤儿文件，不允许元数据指向不存在的文件。

## 活动日志

`entity_events` 记录实体的完整生命周期。

| 字段 | 说明 |
|---|---|
| `id` | 事件 UUID |
| `entity_id` | 实体 UUID，**不加外键**，使实体永久删除后日志仍存在 |
| `entity_kind` / `entity_title` | 冗余快照，供实体消失后仍能展示 |
| `batch_id` | 同一次事务的多条变更共享，用于折叠显示与未来幂等 |
| `type` | `created` / `changed` / `kind_changed` / `trashed` / `restored` / `deleted` / `attachment_added` / `attachment_removed` / `reminder_added` / `reminder_removed` |
| `field` | `changed` 时指明字段：`title` / `body` / `status` / `due` / `start` / `priority` / `list` / `section` / `pinned` … |
| `old_value` / `new_value` | 标量字段两边都存；文本字段只存 `new_value` |
| `occurred_at_utc_ms` | UTC 毫秒 |

### 记录规则

- **只记录实质变更**。保存后值未变则不产生事件。
- **标量字段**（状态、时间、优先级、清单、分区、置顶、重复）改一次记一条。
- **文本字段**（`title`、`body`）按**编辑会话**记录：开始编辑时分配独立会话 UUID，并记录该编辑器的初始快照；会话结束于失焦、切换实体、关闭窗口或退出程序。会话结束时若内容相较会话开始有变化，记一条，`new_value` 存**完整新内容**。同一实体的详情页和桌面便签可以同时编辑，各自使用独立会话，不共享基线。
- 文本类事件只存 `new_value`，某次编辑的"改前内容"由上一条同字段事件的 `new_value` 推导，首次编辑的"改前"为创建事件中的初值；这样任意两点之间都能完整还原，而不必把存储翻倍。
- 清单项的勾选是离散动作，逐次记录：`field = checklist.<条目UUID>.done`，`old_value/new_value` 分别为 `0/1`。清单项文本编辑并入该编辑器所属的实体会话：会话结束时，每个实际改动的现存条目记一条，`field = checklist.<条目UUID>.text`，只存完整新文本到 `new_value`；未变化条目不记录。正文 `- [ ]` 不产生日志。
- `kind_changed` 必须记录前后 `kind`；因字段保留，日志中标注"字段已保留"而非"已删除"。
- 纯本机状态不记录：桌面几何、窗口层级、提醒投递凭证、界面偏好。

### 存储与访问

- **不设上限**，不做裁剪。实测规模下（正文 2 KB、每实体数十次编辑、数百实体）整库仍在几十 MB 量级。
- 日志**不进入全量内存快照**；按实体惰性查询，索引 `(entity_id, occurred_at_utc_ms)`。
- 日志是只增不改的业务数据，随实体同步，永久删除后仍保留。

## 备份 `.klb`：全量导出与覆盖恢复

备份是**镜像**，不是增量：一次导出再导入，业务数据与导出前完全一致。

### 导出

- 导出当前数据库的**全部业务数据**，不按清单或当前视图裁剪。
- 包含：`folders`、`lists`、`sections`、`recurrence_series`、`entities`、`checklist_items`、`tags` / `entity_tags`、`reminders`、`recurrence_links`、`attachments`（元数据与内容）、`view_defs`、`entity_events`。
- 根元数据显式保存 `defaultTimezone`；系统收集箱由备份清单中唯一的 `is_inbox=1` 记录恢复，不另存工作区或默认工作区 ID。
- 不包含设备本地数据：`installation_id`、`device_id`、`desktop_notes`、`reminder_deliveries`、`signed_in`、`sync_bindings`、`tombstones`、`outbox`。因此窗口位置与提醒投递记录不随备份回滚，它们属于设备而不是数据。
- 使用原子写入，中途失败不留下半个文件。

### 导入：先清空，再写入

1. 完整解析并校验容器（边界、UUID、引用完整性、状态与时间、RRULE、附件大小与 SHA-256）；任何一项失败都在动库之前终止。
2. 附件内容先写入暂存位置；在数据库事务提交前完成可恢复的新旧文件交换，任一步失败都恢复原文件并回滚数据库。
3. 单个事务内清空全部业务表，再按备份内容重建。`local_meta` 不整体清空：保留本机 `installation_id`、`device_id`，从备份唯一的系统收集箱恢复 `inbox_list_id`，从根元数据恢复 `default_timezone`，清空 `signed_in` 与同步游标。
4. 提交成功后仅清理旧附件备份，关闭全部便签与详情、重建导航与列表。替换期间禁止旧编辑器继续提交；失败时保留原界面与本机数据。
5. 失败则回滚事务、恢复原附件并清理暂存文件，本机数据保持原样。

- **UUID 原样保留**：正文里的 `kl:` 内链、活动日志的 `entity_id`、重复链接与提醒归属都不需要改写。
- 导入是**破坏性操作**：必须二次确认，确认文案写明"本机现有全部任务、笔记与清单都会被删除"，并提示先导出。
- 导入完成后，对 `trigger_at` 不晚于导入时刻的提醒写入本机投递凭证、**不补发**，避免历史提醒集中弹出；未来提醒照常生效。
- 旧 `.knb`、旧 `.json` 与其他旧格式不迁移、不导入。

### 格式与上限

- 容器魔数 `KLB1`，元数据标识 `KylinList.Entities`，版本 2。
- 容器总大小 2 GiB；元数据块 256 MiB，超出时返回明确错误，不解析、不部分写入；单个附件仍为 2 MiB。
- 附件内容按帧流式读写，不整体载入内存。

## 并发与事务

- 每条可变、可同步业务行都有 `revision`；更新与删除以 `revision` 为条件，陈旧写入必须被拒绝而不是覆盖。`entity_events` 是只增不改的追加日志，不参与更新或删除 CAS，是这条规则的明确例外，不设置 `revision`。
- 一次业务操作涉及的所有行（实体、清单项、提醒、附件元数据、重复链接、日志事件）在同一事务内提交。
- **修订推进规则**：会改变实体状态或关联数据的操作必须推进该实体的 `revision`，包括导入/移除附件、创建或迁移子任务。否则陈旧快照的删除会绕过保护，级联删掉新数据。
- 只在提交成功后替换内存快照并发信号；失败时保留原快照与用户编辑内容。
- 多表读取必须来自同一快照（单个读事务）。

## 同步预留

`sync_bindings`、`tombstones`、`outbox` 只为未来可选账号同步预留。

- **未登录时，`sync_bindings`、`tombstones`、`outbox` 必须保持为空**；普通本地操作不得累积同步历史，首次绑定以全量快照为基线。
- 预留 outbox 带 `batch_id` 与 `base_server_revision`，用于未来整批幂等确认。
- 首次登录时：对方为空则上传，本地为空则下载，双方都有数据必须由用户显式选择，不能静默覆盖。
- 客户端不保存密码、密码哈希或令牌；令牌属于未来服务端与系统安全存储的职责。

## 扩展边界：哪些改动会动库，哪些不会

数据模型的目标是**此后只改交互逻辑、不再改库**。为此区分两类改动：

**不需要改库**（新增列、新增表、新增索引都属于这一类，SQLite 支持就地 `ADD COLUMN`）：

- 新增视图、视图段、排序规则 → 只写 `view_defs.spec_json` 或代码里的内置定义；
- 新的提醒方式（如"截止前 N 分钟"）→ 给 `reminders` 增加 `anchor` / `offset_minutes` 两列；
- 全文搜索、看板/日历渲染、拖拽排序、批量操作、内链预览样式、日志展示与裁剪 → 新增派生表或纯代码；
- 重复规则扩展（`BYDAY` / `COUNT` / `UNTIL`）→ `rrule` 是文本，只改引擎；
- 同步 → 新增游标表与边表。

**需要一次性表重建**（SQLite 改 `CHECK` 或主键要重建表）：

- 新增第三种实体类型（如"习惯""倒数"）、第四种状态；
- 给检查清单项加独立日期或提醒——但这本就应当改用父子任务，而不是改这张表。

因此当前的选择是：**枚举值收紧在 `CHECK` 里**（完整性优先，接受偶发的一次重建），**可变结构塞进 JSON**（视图定义），**不为未证实的需要预留空列**。

## 测试重点

- schema：表、列、索引、外键、CHECK、唯一系统收集箱、`foreign_key_check`、`integrity_check`。
- 实体：UUID 稳定性、`revision` 冲突拒绝、软删除与永久删除。
- 类型：笔记无父子；有子任务或自身为子任务的实体拒绝转换为笔记；转换后任务专属字段保留，转回后完全复原。
- kind 过滤：带提醒、带截止、已完成的任务转为笔记后，不出现在今天/日历/已完成，提醒永不触发。
- 视图：置顶排序前缀、过期按日期分块、时间视图先过滤后分块、无日期与笔记的位置、全序稳定。
- 内链：解析、渲染取目标当前标题、断链降级、回收站标记、反向引用查询。
- 日志：标量逐次、文本按会话、只存新值可还原、关闭程序不丢最后一条、永久删除后仍可读。
- 检查清单：正文 `- [ ]` 不计入进度、不可点。
- 备份：导出全部业务数据；导出→覆盖导入后逐表一致；UUID、内链、日志与重复链接不变；导入失败回滚且本机数据完好；超限在动库前拒绝；恶意容器拒绝。
- 提醒：重启去重、`kind` 过滤、多提醒独立投递、导入后不补发过期提醒。
