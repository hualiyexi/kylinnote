# 银河麒麟优先：开发、工具与发布验收

本文将银河麒麟开发者官网工具的选用与项目后续流程联系起来。调查日期：2026-11-07；工具版本是当日官网资源表所列，实际使用前应重新核对官网及目标镜像。**本次只核查公开页面和项目配置，尚未下载、安装或运行这些工具，也未执行目标机测试。**

## 1. 平台目标与证据等级

- **首要目标**：银河麒麟桌面操作系统 V10 SP 系列的实际部署环境。具体 SP、补丁、镜像和 CPU 架构尚待以目标机器确认，不推断为 SP1、ARM64 或某一种桌面会话。
- 仓库目前提供以 ARM64/X11 为主的 Linux 构建、打包路径；这反映现有工程能力，不代表用户已经确认所有目标机都是 ARM64，也不证明已经在目标麒麟镜像验收。
- Windows 只用于开发预览、辅助调试和必要回归，不是替代麒麟的发布验收平台。Ubuntu 20.04 ARM64 容器是参考构建和自动化环境，不是目标麒麟镜像。
- 区分 **参考环境自动化通过 → 指定麒麟环境实测通过 → 厂商正式认证**。后一等级不能由前一等级自动推导。openKylin、Ubuntu、麒麟 V10 和 V11 不能混同。
- 正式交付前须完成实际目标镜像上的必要验收并保存证据；目标 SP、架构或镜像未明确时，可以继续开发，但不能声称目标兼容验收通过。

## 3. 建立目标环境

1. 在目标麒麟机器或与正式部署一致的可用环境，记录系统完整名称、SP/更新号、镜像标识及补丁，CPU 型号和架构、内核、图形会话（X11/Wayland）、桌面/窗口管理器、图形驱动和屏幕缩放。涉及联网时记录网络限制；不要把机器身份信息公开。
2. 优先评估官网系统版本查询工具；必要时结合系统提供的 `/etc/os-release`、`uname`、`dpkg --print-architecture` 等只读信息。若字段冲突或不能确定 SP，以厂商资料和实际部署镜像为准，不自行猜测。
3. 记录编译器、CMake、Qt、glibc/libstdc++、Qt 插件和软件源。建立该环境与应用版本、Git commit、构建配置、包版本及 SHA-256 的对应关系。
4. 准备环境时评估 EnvDeploy；下载安装任何工具前核对官网提供的版本、架构、完整性、许可证及来源。依赖离线导入前另行核对来源与版本。

## 4. 开发及日常检查

1. 保留 Qt Widgets/CMake/SQLite 路线。Windows 可用于快速查看和调试，但涉及系统行为的设计要以目标麒麟为准。引入 KylinSDK 或新的图形运行时前，先评估目标 SP、CPU、离线部署和许可。
2. 保留现有单元/UI 测试，测试发生变化时在适用的环境运行；界面开发需安排麒麟真实桌面回归。Qt 的 `offscreen` 测试可检查一部分逻辑，不能证明真实桌面集成。
3. 任务交互改动重点检查：创建与编辑、保存/失败提示、完成与恢复、右键菜单及键盘操作；日历重点检查日期展示、跨月/闰日、时区与重复规则（按实际支持范围）；搜索重点检查中文输入法、范围、大小写、空结果和结果定位。
4. 涉及桌面集成时检查中文输入法与字体、通知和托盘、便签层位、窗口尺寸与多屏/DPI、自启和单实例。离线使用、任务数据库与备份不能被这些调整破坏。
5. 能在目标麒麟机上针对变更做实际验证时优先完成；暂不可用时明确记为“未在目标麒麟验证”，不得把 Windows 或 Ubuntu 的通过改写为麒麟通过，也不得据此宣称可正式交付。

## 5. 打包、适配和发布门禁

### 当前项目已有但不能单独替代麒麟验收

- `packaging/build-deb.sh` 支持现有原生 ARM64/amd64 路径、常规包与 bundle、架构及部分依赖检查；`packaging/test-bundle.sh` 在隔离环境检查 bundle 安装和启动。参见[构建文档](building.md)。
- 现有 Linux CI 是 Ubuntu 20.04 ARM64 容器，不是银河麒麟；Windows CI 是辅助验证。两者有价值，但都不是指定麒麟目标机验收。
- 当前 `.github/workflows/build.yml` 已移除自动创建 Release 的 job 和写权限；CI 只提供参考候选制品，不会替代目标麒麟设备验收。旧标签对应的旧工作流及已排队运行不会被本地改动追溯改变。
- `packaging/deb/DEBIAN/control` 已移除未经确认的 SP1/ARM64 兼容表述；系统 Qt 依赖下限按实际构建 Qt 版本记录。包元数据、压缩格式或哈希检查均不能单独证明目标环境兼容。

### 每个正式交付候选包

1. 锁定目标系统/SP/补丁/CPU/桌面和候选包哈希；使用与目标兼容的构建环境。核对包架构、系统库、Qt 与插件、图标、desktop 文件、依赖和许可证。
2. 如工具版本、授权与目标环境合适，运行 KAT 做环境、包规范及兼容性检查；系统/依赖迁移时评估使用 PkgCompat。保留工具版本、目标环境、结果和报告。**无法取得工具结果时写明原因及未验证状态，不能写成工具通过。**
3. 用目标镜像执行实际安装、启动、退出、升级、卸载和离线依赖检查；确认卸载、失败和升级场景不意外损坏用户数据。使用隔离测试数据，不直接操作真实业务库。
4. 在目标桌面完成任务、日历、搜索及相关输入法、托盘、通知、窗口/便签等适用回归；记录失败、阻断项、复测结果与验收人。未实现的功能不标记通过。
5. 将 commit、构建环境、包名/SHA-256、目标镜像、测试时间、报告和结论关联归档；检查记录不包含私密账号、个人任务或不必要的设备身份信息。外发源码、安装包、机器信息或报告前取得单独授权。
6. 所有必需的目标机验收项通过后才按项目发布流程交付。若要声称厂商认证，还须单独完成并保存厂商认证要求的证据；本项目自测或 KAT 报告本身不等于认证。

验收时自行记录候选包哈希、目标镜像和每一项实际结果；目标麒麟镜像上的 deb 依赖、输入法插件和真实桌面行为必须由验收人实际检查。CI 只产出候选包并在 Ubuntu 参考环境验证，不构成目标机验收。

第三方麒麟容器及剪贴板项目的评估见[容器与剪贴板兼容性参考](research/kylin-container-and-clipboard.md)：仅在核验来源、镜像实际用户态、具体目标版本和架构后，将容器作为 deb 预检的补充；不能替代目标桌面验收。打包时也应核对 deb 压缩格式与目标 dpkg，不能直接沿用其他项目的环境假设。
