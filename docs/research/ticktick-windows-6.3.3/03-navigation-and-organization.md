## 1. 组织层级不要混为一谈

官方《如何管理海量任务》的索引摘要列出：**文件夹 → 清单 → 分组 → 任务 → 子任务**。这说明它们是不同层级，不代表所有任务都必须经过五层。来源：[官方文章，正文未完整取回](<https://help.dida365.com/articles/6950652964327391232>)。

```text
组织结构                         交叉分类                 显示方式
文件夹                           标签 A / 标签 B           列表 / 看板 / 时间线
  └ 清单（工作项目）              同一任务可多标签          日历（按时间组织）
      └ 分组（项目内的阶段）
          └ 任务
              └ 子任务
```

这是根据资料整理的**概念示意，不是当前窗口截图或数据库结构**。

- **文件夹**聚合多个清单，解决导航规模问题。
- **清单**是任务的组织容器，不等于列表这种显示方式。
- **分组**是清单内部的划分，不宜直接和 KylinNote 现有的“分组”同名对齐。
- **标签**是跨容器的多对多分类；官方摘要明确一个任务可以有多个标签。来源：[用标签管理任务](<https://help.dida365.com/articles/6950656299306582016>)。
- **智能清单**按条件聚合任务，不应天然等同一个可随意搬入任务的普通容器。

## 2. 侧栏应按三类记录

| 类别 | 本轮证据 | 现场应检查什么 |
|---|---|---|
| 智能清单 | 旧版官方正文列所有、今天、明天、最近7天、分配给我、事件、已完成、垃圾桶；本地有智能清单设置组件 | 当前实际名称、顺序、显示/隐藏/自动、计数定义、空时是否消失 |
| 用户组织 | 官方摘要支持文件夹/清单/分组层级；本地中文库有新建文件夹、编辑文件夹、归档等相关文案 | 右键差异、颜色、图标、归档与删除区别、重排与展开 |
| 标签与筛选 | 官方摘要支持多标签；本地过滤器组件引用清单、标签、日期、优先级、指派人、关键词 | 标签显示开关、嵌套/合并、AND/OR/NOT、搜索范围与空态 |

**旧版智能清单列表不能充当本机当前导航清单。** 账号权限、配置、版本及模块开关都可能改变可见项。

### 智能清单的可见性

[官方旧版 FAQ：为什么看不到某些智能清单](<https://help.dida365.com/faqs/6427789969573543936>)正文确认三种模式：

- **显示**：固定出现在侧栏。
- **隐藏**：不出现在侧栏。
- **自动**：有未完成任务时显示，没有时隐藏。

旧文 Windows 路径为“头像 → 设置 → 偏好与功能 → 智能清单”；这个路径应标为**旧版说明**。本地资源存在 `smartlistconfig` 只支持当前安装含相应组件，不能证明路径名称仍一样。

## 4. 搜索与导航状态应怎样实测

至少区分四种入口：全局搜索、当前清单过滤、标签聚合、自定义条件筛选。它们可能使用同一个输入样式，却有不同结果范围。

对每个入口记录：

1. 入口位置、快捷键和搜索占位文案。
2. 标题、正文、子任务、标签、已完成、回收站是否参与匹配。
3. 输入后立即检索还是按 Enter；中文输入法组合过程是否误触发。
4. Esc 是清空、退出搜索，还是关闭详情；返回后是否恢复原清单、选中项、滚动位置。
5. 无结果时是否说明搜索范围；清空搜索后是否保留原排序/分组。

以上是**研究问题，不是本机行为结论**。

## 5. KylinNote 的对应关系

| 滴答概念 | 本项目目前对应 | 改造影响 |
|---|---|---|
| 清单级容器 | 当前 `TaskGroup(id,name)` + `Task.groupId` | 可以先改导航呈现；不要因当前叫“分组”就声称已支持滴答清单内分组 |
| 智能清单 | `TaskView` 和 `TaskFilter` | 已有今天、逾期、重要等，语义应先固定 |
| 标签聚合 | 已存任务标签，但 `TaskView` 无标签视图 | 可先扩展过滤/导航，不必立刻迁移 Task 表 |
| 文件夹/清单内分组 | 当前缺层级、缺专门分区字段 | 若确实需要，应独立设计数据模型与迁移 |
| 手动顺序 | 当前四种自动排序；无任务手动排序字段 | 不能把便签窗口 `zOrder` 当任务排序复用 |
