# 04｜任务列表、详情与核心操作

## 1. 快速记录：先确认新任务落到哪里

旧版 Web 参考图显示，当前清单标题下方有快速添加输入，文案包含“添加任务至收集箱，回车即可保存”。这只描述 [所附官方旧图](<assets/official-web-layout-reference.png>)。

本地中文资源有当前清单/收集箱相关添加占位文案，并有“任务默认值”“默认日期”“默认清单”“默认添加到”等设置组件。因此至少要区分：

- 当前普通清单内添加。
- 智能清单（今天/最近7天）内添加。
- 全局悬浮添加。
- 搜索、标签、日历时间格内添加。

不能仅凭一个占位文案推定默认日期或归属规则。

**官方旧帮助正文：**Windows 全局添加为 `Ctrl+Shift+A`，可以在其他应用中打开悬浮输入框，输入后回车。来源：[全局添加快捷键](<https://help.dida365.com/tips/6427415929369395200>)。它是全局快捷键文档记录，不是本机已测；可能受自定义快捷键与系统冲突影响。

**本地资源：**智能识别组件引用“日期识别”“移除文本中的日期”“标签识别”“移除任务标题中的标签”“网址解析”。只确认组件文案，不确认用户开关、识别语法、提交时机或准确率。资源证据见 [smartrecognitionconfig](<resource-evidence.json>)。

## 2. 任务行的信息与命中区

对本机任务行，尚不能填写行高、右侧图标、hover 操作或日期格式。建议后续按以下单元观察：

| 单元 | 待确认问题 | 对改造的意义 |
|---|---|---|
| 完成框 | 左键是否直接完成；有无重复任务确认；命中区与选中区是否分离 | 防误完成、统一保存路径 |
| 标题 | 单击选择、双击编辑或开窗？长标题如何截断？ | 列表和详情的主从关系 |
| 日期/时间 | 逾期、今天、跨日、全天如何显示；日期是否直接可点 | 信息压缩与快捷安排 |
| 元信息 | 标签、所属清单、描述、子项进度、附件、提醒如何取舍 | 避免第二行所有内容挤成一串 |
| 行尾操作 | 悬停出现哪些按钮、是否有工具提示/快捷键替代 | 发现性与密度的平衡 |
| 选中/焦点 | 右键是否先选中；键盘上下移动是否跟随详情 | 多入口状态一致性 |

## 3. 详情组件的本地证据

安装包存在下列组件名：

- `views/detail/taskdetailhead.baml`
- `views/detail/taskdetailbottomcontrol.baml`
- `views/detail/taskdetailmorecontent.baml`
- `views/detail/taskdetailbatchcontrol.baml`
- `views/detail/taskdetailpopup.baml`
- `views/detail/taskdetailwindow.baml`
- `views/mainlistview/detailview/linkparenttaskmenu.baml`

它们说明安装包含头部、底部、更多、批量、弹层/窗口、关联父任务等细分资源。**名字不是布局图**：不能直接写成“某按钮必在右下角”或“单击一定弹窗”。资源清单见 [精简证据](<resource-evidence.json>)。

### 优先级

官方《任务详情与编辑》摘要明确四档：**高、中、低、无优先级**；本地过滤组件也引用这四个标签。来源：[官方文章，正文未完整取回](<https://help.dida365.com/articles/6950661731483910144>)。

本项目只有 `priority=0..2`。不能把滴答四档直接画进下拉框，却仍按旧模型保存；要么明确映射与合并，要么新增等级并迁移数据。

### 日期、提醒、重复

本地“任务默认值”组件分别引用默认日期、日期模式、默认时间段、有时间任务提醒、全天任务提醒等。可确认它区分相关设置概念，**不能从中推出日期弹层完整控件、重复规则集合或提醒个数**。

后续须分别观察“无日期、全天、有时刻、时间段、重复、多个提醒”的 UI；操作会改动任务时只记录入口，不提交。

### 正文与格式工具

本地编辑器资源明确引用：标题1/2/3、加粗、斜体、下划线、删除线、高亮、检查项、无序/有序列表、分割线、时间、链接、代码、引用、附件等短文案。

编号菜单另有“继续之前的编号 / 开始新列表 / 修改编号”。这说明正文编辑不只有一个纯文本框。**不能据此推定存储格式、渲染引擎或键盘行为已验证**。详细菜单边界在 [菜单专项](<05-context-menus.md>)。

### 附件

[官方旧 FAQ](<https://help.dida365.com/faqs/6684625093496143872>)正文写明：Web/Windows/macOS 从任务详情右下方 `··· → 上传附件` 添加；复制粘贴可直接加图片。该文含旧配额，**本册不把旧限制当当前额度，也未执行上传**。

## 4. 多选与批量编辑

[官方《桌面快捷操作》索引摘要](<https://help.dida365.com/articles/7351502985995747328>)给出：

- `Ctrl+单击` 多选。
- `Shift+单击` 前后两个任务，选中区间。
- 多选后右侧出现编辑菜单，可批量设置日期、优先级、清单、标签。

这属于**选择状态下的批量编辑面板**，不能直接记为“右键菜单”。尚未确认 Ctrl+A 的范围、批量混合值的表现、完成/回收站任务混选以及是否允许跨清单多选。

## 5. 后续需要补齐的交互闭环

每个操作不只拍“打开的那一张”，还应记录：

```text
入口 → 触发方式 → 弹层/详情状态 → 取消/确认规则
    → 保存反馈 → 列表变化 → 导航计数变化 → 焦点和滚动恢复
```

本机保存是自动、失焦提交还是显式提交，目前未知。也没有验证撤销、同步失败、离线、窗口关闭时的草稿处理。不要把“成熟软件应该如此”当实测事实。

## 6. KylinNote 可先实施的方案（建议）

1. **详情上部紧凑元信息**：所属分组、日期/提醒、优先级、星标；正文/子项放在连续阅读区。
2. **低频操作收纳**：便签外观、复制、回收站等放更多操作；贴桌面是本项目核心能力，应保留易发现入口。
3. **快速添加不假装智能**：先提供明确的日期/分组/优先级选择，再考虑自然语言解析；清楚提示新任务落点。
4. **统一命令**：完成框、Space、右键、详情和提醒弹窗，最终走同一保存与状态转换契约。
5. **保存失败优先于外观简化**：不能因模仿无按钮编辑器而取消“保存失败保留内容”的保护。

具体代码与待补测试见 [项目改造映射](<08-kylinnote-adaptation.md>)。
