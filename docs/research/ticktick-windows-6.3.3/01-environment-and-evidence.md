## 2. 为什么本次没有本机界面截图

执行顺序：

1. 收到用户提供的滴答清单应用窗口引用。
2. 仅进行一次连接器发现；未发现覆盖任务的已安装 MCP。
3. 依工具路由使用桌面读取；截图读取和能力读取均返回 `fetch failed`。
4. 只读检查本地应用管理状态：两次桌面连接计划均失败，连接器为 Cua Driver，`installed=false`。
5. 停止重复窗口读取；没有用 PowerShell 自制截图、注入或另一套自动化绕过桌面工具，也没有自行安装驱动或更改批准策略。

**结果：实际桌面快照 0，成功展开菜单 0，成功输入/鼠标操作 0。** 这属于取证通道故障，不是滴答缺少某种功能。

## 3. 证据分类

| 标记 | 来源 | 可以写入的结论 | 不可以写入的结论 |
|---|---|---|---|
| 本机元信息 | 安装文件版本与公共配置 | 版本、框架线索 | 真实窗口布局、当前账号状态 |
| 本地资源 | PE/CLI 公共资源、BAML 文案与键引用 | 组件/文案定义存在、静态令牌值 | 当前显示状态、按钮坐标、菜单完整性、执行成功 |
| 官方正文 | 成功取回全文的官方帮助，部分为旧帮助 | 文章明确说明的操作与适用平台 | 自动推广为本机 6.3.3 行为 |
| 官方摘要 | 官方文章的搜索索引摘录，正文未完整取回 | 摘录中明确的有限事实 | 完整按钮顺序、全部步骤、隐藏选项 |
| 本项目源码 | 当前仓库的 Qt/C++ 源码 | 代码路径、已有字段、静态风险 | 已运行复现的缺陷、已通过的测试 |
| 设计建议 | 为 KylinNote 提出的方案 | 可讨论的实现与验收标准 | 滴答本来就这样做 |
| 本机实测 | 成功读取真实窗口并展开验证 | 本轮没有此类证据 | 不得用其他等级替代 |

完整来源集中在 [来源索引](<10-source-register.md>)。各章会直接标明资料性质，避免读者反复猜测。

## 4. 本地静态资源检查方法

- 使用离线脚本读取可执行文件 PE/CLI 元数据及托管资源索引；**没有通过反射加载或执行滴答程序集**。
- 遍历选定 BAML 字节流的记录边界，读取公共字符串、资源键和引用；选定的 496 个流均走到末尾，解析错误 0。
- 将与中文资源键同名的静态资源引用关联到组件，例如设置“任务默认值”和编辑器的“继续之前的编号”；仅保留选定记录类型并排除已知样式属性，保留属性ID和原始扩展标志供复核。名称匹配仍是候选线索，未完整还原属性所有者和资源作用域，不能保证每个匹配都是可见文案。
- 仅交付短文案、资源名称、相关偏移及少量主题令牌；不分发可执行文件、完整 BAML/XAML、完整翻译库或专有图标。
- [精简证据](<resource-evidence.json>)保留局限、偏移、选取范围和哈希，便于将来重核；它是自编解析器的输出，**不是官方 API，也不是运行时 UI 树**。

### 字号和颜色解释

WPF 的 `Font13=13` 等是资源中的数值；没有测量它在当前 DPI 下的物理像素。`#AARRGGBB` 是 WPF 的 Alpha 在前格式，不要直接当 CSS 的 `#RRGGBBAA`。资源名中的百分比也不能代替实际 Alpha 字节。

## 5. 隐私及数据保护

本次未读取账号凭据、个人偏好文件、任务数据库、任务标题/描述、附件或提醒内容。配图仅来自官方公开帮助和仓库已有示例；所以本轮没有需要遮挡的个人任务截图。

未来实测时：

- 截图只保留选定应用窗口，不采集整个桌面、通知、其他窗口。
- 账号、头像、邮箱、清单名、私人任务、附件名、共享成员等先检查，再作不可逆实色遮挡；不依赖模糊或压缩。
- 原始含隐私图只保留在研究临时区，不放进可能公开的仓库；提交前逐张人工检查。
- 不新增测试任务、不完成/删除现有任务、不拖拽改时间、不修改开关；需要写入验证时另用用户明确允许的隔离测试资料。
