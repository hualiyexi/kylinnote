# 06｜看板、日历与其他功能模块

[返回目录](<README.md>) · [上一章](<05-context-menus.md>) · [下一章：设置与快捷键](<07-settings-and-shortcuts.md>)

## 1. “显示方式”和“功能模块”不是一层概念

- 列表、看板、时间线主要解决**同一批任务如何呈现**。
- 日历按时间组织任务；日历里还可以有自己的“列表视图”，不要与普通任务清单的列表混称。
- 四象限、专注、习惯等是面向不同工作方式的模块。
- 模块是否显示，可能受功能开关、版本、会员和账号状态影响；本轮没有检查本机当前配置。

本地 `views/setting/featureconfig.baml` 引用的模块名称有：日历、四象限、习惯打卡、番茄专注、倒数纪念日、AI。**仅证明安装资源包含这些模块标签，不证明全部可用，更不等于建议本项目全部添加。** 见 [资源证据](<resource-evidence.json>)。

## 2. 列表与看板

[官方《看板视图：分类管理任务》索引摘要](<https://help.dida365.com/articles/6950656501543337984>)将看板说明为清单的显示方式，记录了任务列表右上角更多中的切换视图入口；摘要也提及智能清单、文件夹、标签场景。正文未完整取回，不能由此列出本机所有可切换范围。

**本地看板显示设置引用：**

| 文案 | 可能要解决的问题（研究问题，不是执行结论） |
|---|---|
| 日期显示为 | 绝对日期、相对日期如何切换 |
| 看板尺寸 | 卡片/列密度怎样改变 |
| 显示看板颜色 | 分组色、清单色、标签色如何使用 |
| 显示添加输入框 | 列内快速添加的可见性 |
| 显示检查事项 | 卡片正文/子项信息的取舍 |

组件是 `views/kanban/kanbandisplaysettingwindow.baml`，对应文案见 [精简证据](<resource-evidence.json>)。列头菜单、卡片右键、拖动跨列后的数据语义均未实测。

**项目建议：**只有存在明确“按什么分列”的数据契约时才做看板。按现有分组呈现可先验证；自定义阶段/手动卡序会涉及持久化，不能只改布局。

## 3. 日历

**本地日历显示设置文案：**显示周末、显示已完成、显示检查事项、显示所有重复周期、显示习惯、显示专注记录、显示倒数纪念日、显示课程、辅助时区、时区设置。它们来自 `calendardisplaysettingwindow`，不是当前勾选状态。

本地模块说明还写到“6种日历视图”，但本册没有拿到实际切换器，**不猜测六项确切名称或顺序**。

[官方《列表视图：按天查看任务》摘要](<https://help.dida365.com/articles/6950643979079647232>)描述日历中的列表视图，支持按天查看及时间轴；不能把它当作任务模块普通列表。

[官方《任务与日历同时显示》摘要](<https://help.dida365.com/articles/7358382716586295296>)记录桌面端右键任务模块图标，选择“同时显示日历”，日历出现在任务清单右侧。它说明并列工作区的可能性，不是本机分栏尺寸证据。

**项目建议：**KylinNote 有开始/截止时刻，可先做只读按日查看。但全天语义、未预生成的重复任务、跨日区间和提醒不是“画日历格子”就解决了。拖动修改时间必须经过原有校验与事务。

## 4. 时间线：官方旧版完整正文可核对

![官方旧版时间线界面帮助示例，具体 OS 未核对，非本机截图](<assets/official-timeline-reference.png>)

来源：[官方旧版时间线帮助](<https://help.dida365.com/tips/6912963677121413120>)；文章覆盖 Windows/Mac/Web，未确认这张图的具体 OS，不代表本机当前版本。

该旧文明确说明：

- 普通清单右上角更多 → 视图 → 时间线视图。
- 当时的所有、收集箱、今天、最近7天等智能清单不支持时间线。
- 横向查看任务，可切换天/周/月显示比例。
- 在日期空白位置添加任务会带上所点日期。
- 无时间任务在右侧“安排任务”；可拖到时间线安排时间。
- 拖动任务边缘改变时长，拖动任务块改变起止位置。

这些操作会写入任务，**本轮没有执行**。旧文所说的支持范围不自动等于当前 6.3.3 支持范围，也不与看板的范围混用。

本地时间线显示设置引用“任务块颜色”“显示星期”“显示检查事项”；短说明提及按清单、标签、优先级呈现颜色。这使得颜色的来源成为后续需要记录的一个维度。

## 5. 四象限

[官方摘要](<https://help.dida365.com/articles/6950398710203285504>)记录桌面端从头像 → 设置 → 功能模块开启四象限，按紧急、重要两个维度管理。本地有 `Matrix` 标签。

**注意：**紧急/重要不一定就是四个固定优先级；未核验象限默认筛选、是否可自定义、拖到其他象限会改什么字段。

**项目建议：**先定义现有日期/优先级与象限规则，再决定是否需要独立视图；“重要与星标”的当前语义不可悄悄重写。

## 6. 番茄专注与习惯

| 模块 | 官方摘要/本地资源 | 本机缺口 |
|---|---|---|
| 番茄专注 | [官方摘要](<https://help.dida365.com/articles/6950670128287580160>)记录设置→功能模块启用；本地有番茄时长、短/长休息、间隔、自动开始、提示音、Mini模式等文案 | 开关、当前计时、暂停/结束、关联任务、统计、声音行为未测 |
| 习惯打卡 | [官方摘要](<https://help.dida365.com/articles/6950379455722291200>)记录设置→功能模块→习惯打卡；本地有在今天/最近7天显示的相关组件文案 | 创建字段、打卡规则、补记与统计未测 |

旧 Web 专注帮助把开关放在“实验功能”，与新桌面摘要不同。见 [旧 Web 文档](<https://help.dida365.com/faqs/6684765710167572480>)，不要统一改写为一条当前 Windows 路径。

## 7. 小部件、倒数纪念日、AI：只记范围，不盲目扩张

本地小部件设置引用主题、不透明度、分组排序、置于顶层、贴近屏幕边缘自动隐藏、显示输入框/已完成等。AI 设置资源还引用用量、隐私、关联、MCP 服务器。此处仅列资源范围；**没有操作账号、联网配置、MCP 或 AI，也没有确认功能入口/权限。**

KylinNote 已有桌面便签这个核心特色。优先借鉴轻量小窗、层位和阅读/编辑的分工，远比同时增加专注、习惯、课程、AI 更符合当前项目规模。
