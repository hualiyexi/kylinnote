# Goal：滴答清单 Web 全区域设计参考手册

日期：2026-11-07。用户要求：全面研究 UI、设计风格、功能布局、不同位置右键菜单；不仅截图，还研究实际前端代码。

## 目标

产出可直接指导 KylinNote 后续改造的分区域参考手册：说明界面分区、控件位置、交互状态、菜单差异、实际 DOM/CSS/JavaScript 实现证据，以及适合离线 Qt 项目的改造建议。

## 验收标准

1. 总体布局、导航组织、任务列表、任务详情、上下文菜单、视图模块、设置/快捷键分别成章。
2. 关键位置附现场截图或 DOM/代码证据。截图不代替代码检查，代码静态存在不代替运行实测。
3. 每类入口标记：已实测、仅代码可见、受会员/权限限制、未验证。未达覆盖的项明列，不宣称穷尽所有账号/平台/版本状态。
4. 代码记录发布资源、哈希、定位词/偏移；若 source map 可公开取得，只在明确范围内核对，不取得账号 API/隐藏 state。
5. 菜单区分右键、更多按钮、悬停子菜单和批量编辑；记录分组、禁用与风险操作，不执行写入。
6. 不修改任务、清单、账号、订阅和设置；不发起 AI 请求或专注计时/打卡。
7. 公开文档不含账号原文、私人任务/清单/附件信息。原始截图不进入仓库，交付图片脱敏或裁成纯控件局部。
8. 事实与 KylinNote 改造建议分离；不照搬品牌图标/插画/产品文案或发布 bundle；不将 Web 结论冒充 Windows 客户端结论。
9. 此次研究在 ZCode 内置 Chromium 浏览器进行，不是 Chrome 78 兼容测试。后续项目 UI 测试仍须以 C:/Chrome78 Chromium 78 为兼容起点。

## 边界

“全面”以当前登录账号实际可见的主要区域和明确发现的入口为范围，不等于逆向完整服务或保证覆盖每个会员/协作/平台特例。缺项留可执行的续查清单。
